# Unity Input System in DOTS

In Unity Entities, simulation logic resides in unmanaged, Burst-compiled `ISystem` structs. However, the modern Unity Input System (`com.unity.inputsystem`) is a managed library. Bridging user input into ECS requires generating an unmanaged-friendly C# action wrapper, polling it synchronously inside a managed `SystemBase` bridge during the initialization phase, and writing the input snapshot into unmanaged ECS components.[^unity-input-system-generated-cs]

---

## 1. The Input Architecture in DOTS

To guarantee deterministic simulation across worker threads, input flows through a single-direction pipeline:

```
[Hardware Input]
       │
       ▼
[Autogenerated Input Actions Wrapper (C# Class)]
       │
       ▼ (Polled during InitializationSystemGroup)
[Managed SystemBase Bridge]
       │
       ▼ (Writes pure unmanaged data)
[Unmanaged Component: PlayerInput (IComponentData)]
       │
       ▼ (Read concurrently across worker threads)
[Burst-Compiled ISystem Structs (Movement, Combat, Camera)]
```

* **Single Source of Truth**: Simulation systems never call `UnityEngine.Input` or managed action wrappers directly. They consume exclusively from unmanaged input components.
* **Update Phasing**: Input polling runs inside `InitializationSystemGroup` so that all subsequent physics (`FixedStepSimulationSystemGroup`) and gameplay systems (`SimulationSystemGroup`) process the exact same frame-synchronized snapshot of input.

## 2. The Autogenerated C# Action Wrapper

Before writing any ECS bridge code, you must generate a strongly typed C# class from your Input Actions asset:[^unity-input-system-generated-cs]

1. Select your `.inputactions` asset in the Project window (e.g., `Assets/Input/InputSystem_Actions.inputactions`).
2. In the Inspector, check **Generate C# Class**.
3. Specify the class name (e.g., `InputSystem_Actions`) and target file path.
4. Click **Apply**.

> [!CAUTION]
> **Never Manually Edit Autogenerated Files**: Any manual edits made to `InputSystem_Actions.cs` will be permanently erased whenever the Input Actions asset is re-saved or regenerated in the Editor. If you need helper methods or properties, extend the class using a separate `partial class` file.

> [!NOTE]
> **Missing Type Compilation Error**: If you receive a compilation error stating that `InputSystem_Actions` does not exist, the **Generate C# Class** checkbox in the asset Inspector has not been enabled or applied.

---

## 3. Polling for Input

In ECS, user input is acquired strictly via **polling** inside `OnUpdate()`, rather than through asynchronous C# event callbacks (such as `action.performed += ...`).

* Continuous values are read using `action.ReadValue<T>()` or `action.IsPressed()`.
* Transient edge actions are polled using `action.WasPressedThisFrame()` or `action.WasReleasedThisFrame()`.

By polling within the system update loop, input collection remains aligned with the frame lifecycle and avoids asynchronous race conditions or garbage collection allocations.

## 4. Canonical `SystemBase` Input Bridge

Because the autogenerated `InputSystem_Actions` is a managed class, the bridge system inherits from `SystemBase` and updates inside `InitializationSystemGroup`:[^unity-entities-systembase][^unity-entities-update-order]

### Step 1: Declare Unmanaged Input Component
```csharp
using Unity.Entities;
using Unity.Mathematics;

public struct PlayerInput : IComponentData
{
    public float2 Movement;
    public bool JumpRequested;
    public bool FireHeld;
}
```

### Step 2: Implement Managed Bridge System
```csharp
using Unity.Entities;
using Unity.Mathematics;
using UnityEngine;

[UpdateInGroup(typeof(InitializationSystemGroup))]
public partial class PlayerInputBridgeSystem : SystemBase
{
    private InputSystem_Actions _inputActions;

    protected override void OnCreate()
    {
        // 1. Instantiate and activate the autogenerated action wrapper
        _inputActions = new InputSystem_Actions();
        _inputActions.Enable();

        // 2. Only update if entities exist requiring input
        RequireForUpdate<PlayerInput>();
    }

    protected override void OnUpdate()
    {
        // 3. Poll hardware states synchronously
        Vector2 rawMove = _inputActions.Player.Move.ReadValue<Vector2>();
        bool jumpPressed = _inputActions.Player.Jump.WasPressedThisFrame();
        bool fireHeld = _inputActions.Player.Attack.IsPressed();

        // 4. Publish unmanaged snapshot to ECS components
        foreach (var input in SystemAPI.Query<RefRW<PlayerInput>>())
        {
            input.ValueRW.Movement = new float2(rawMove.x, rawMove.y);
            input.ValueRW.JumpRequested = jumpPressed;
            input.ValueRW.FireHeld = fireHeld;
        }
    }

    protected override void OnDestroy()
    {
        // 5. Clean up managed instance
        if (_inputActions != null)
        {
            _inputActions.Disable();
            _inputActions.Dispose();
        }
    }
}
```

### Step 3: Consume in Burst-Compiled `ISystem`
```csharp
using Unity.Entities;
using Unity.Transforms;
using Unity.Mathematics;
using Unity.Burst;

[BurstCompile]
[UpdateInGroup(typeof(SimulationSystemGroup))]
public partial struct PlayerMovementSystem : ISystem
{
    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        float dt = SystemAPI.Time.DeltaTime;

        foreach (var (transform, input, speed) in 
            SystemAPI.Query<RefRW<LocalTransform>, RefRO<PlayerInput>, RefRO<MovementSpeed>>())
        {
            float3 moveDirection = new float3(input.ValueRO.Movement.x, 0f, input.ValueRO.Movement.y);
            transform.ValueRW.Position += moveDirection * (speed.ValueRO.Value * dt);
        }
    }
}
```

## 5. Continuous vs. Transient Inputs

| Input Kind | Hardware Example | Polling Method | Consumption Behavior |
| :--- | :--- | :--- | :--- |
| **Continuous** | Analog stick, WASD, Trigger pressure | `.ReadValue<T>()`, `.IsPressed()` | Persists as long as the user holds the input; overwritten every frame. |
| **Transient (Edge)** | Jump button, Dash trigger, Reload click | `.WasPressedThisFrame()` | Discrete event; downstream systems should consume and reset the flag to prevent duplicate activations across multiple ticks. |

> [!TIP]
> When integrating with fixed-timestep physics (`FixedStepSimulationSystemGroup`), buffer transient triggers inside a `DynamicBuffer<InputEvent>` or reset the flags at the end of the simulation group to avoid missing inputs during frame rate divergence.

## 6. Alternative: MonoBehaviour Input Bridge

In projects where the UI (UI Toolkit or UGUI) manages or consumes input before gameplay systems, a standard `MonoBehaviour` can poll input and push data to an ECS singleton:

```csharp
using UnityEngine;
using Unity.Entities;
using Unity.Mathematics;

public class UIPlayerInputBridge : MonoBehaviour
{
    private InputSystem_Actions _input;

    void Awake()
    {
        _input = new InputSystem_Actions();
        _input.Enable();
    }

    void Update()
    {
        var world = World.DefaultGameObjectInjectionWorld;
        if (world == null || !world.IsCreated) return;

        var em = world.EntityManager;
        em.CompleteAllTrackedJobs();

        var query = em.CreateEntityQuery(typeof(PlayerInput));
        if (query.HasSingleton<PlayerInput>())
        {
            Vector2 raw = _input.Player.Move.ReadValue<Vector2>();
            em.SetComponentData(query.GetSingletonEntity(), new PlayerInput
            {
                Movement = new float2(raw.x, raw.y)
            });
        }
    }

    void OnDestroy()
    {
        _input?.Dispose();
    }
}
```

## 7. Best Practices & Guidelines

* **Wrapper Setup**:
  * *Prefer*: Generating a strongly typed C# class via the Input Actions asset Inspector.
  * *Avoid*: Manually editing the autogenerated `InputSystem_Actions.cs` file.
* **Polling Model**:
  * *Prefer*: Polling input synchronously in `OnUpdate()` via `.ReadValue<T>()` and `.WasPressedThisFrame()`.
  * *Avoid*: Subscribing to C# event callbacks (`action.performed += ...`) inside ECS systems.
* **Group Sequencing**:
  * *Prefer*: Updating input bridge systems inside `InitializationSystemGroup`.
  * *Avoid*: Polling input inside `SimulationSystemGroup`.
* **Component Design**:
  * *Prefer*: Unmanaged `IComponentData` structs as the sole input interface for downstream systems.
  * *Avoid*: Calling managed input APIs from Burst-compiled `ISystem` structs.
